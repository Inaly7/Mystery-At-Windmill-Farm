# 风车农场悬案 UNITY挑战赛 作品说明文档

## 一、项目简介

### 1.1 游戏简介

《风车农场悬案》是一款 3D Lowpoly 轻推理游戏。玩家扮演一只名叫芦笛（Reed）的绿头鸭，走进一座色彩明快、像盒子盆景一样的微缩农场，调查劳模母鸡淑芬丢失的、画有爱心标记的宝贝蛋。

农场里的动物各说各话：小鸡侦探团在撒谎，大黄宿醉后认错了嫌疑人，悲伤蛙把寻常夜景读成惊悚预言，乌鸦把假蛋当成宝贝囤在屋顶。玩家要在这些「跨频道聊天」里收集物证、核对矛盾，把一场看似惊悚的失踪案拼回它真正的样子。全流程约一小时，前段是荒诞误导，终局收成一次温柔的情感反转。

作品使用团结引擎 1.10.1 开发，目标发布平台为 Steam，支持设备为 PC。可运行场景为 `Assets/Scenes/Mechanics_Code.unity`，操作方式为第三人称行走、跳跃与键鼠交互。

初版曾上线抖音小火人世界，约五万人游玩，并获得大量好评。初版使用 Lua 编写逻辑，并用 Lua 存储数据。当前版本把运行逻辑改为 C#，把运行时数据改为 JSON。

### 1.2 核心玩法

本作是一款由轻度平台跳跃支撑的探索推理游戏。点击对话承担推理，跳跃和走位承担探索与收集，二者一起撑起「在农场里办案」。

主循环是：

1. 在农场中行走、跳跃，接近角色与环境。
2. 按交互键触发气泡对话，或调查木炭、羽毛、脚印、白石头等物证。
3. 侦探笔记本按当前进度自动写入线索、假设和下一步去向。
4. 假设被推翻后，笔记本当场划掉旧结论并补上新结论。
5. 向角色出示特定物证，解锁更深的对话。
6. 拾取散落的奶酪碎，向墙缝里的老鼠兄弟兑换情报。

单局按一条主案件推进：

| 阶段 | 玩家感受 | 玩法重心 |
| --- | --- | --- |
| 起因 | 焦急，带一点轻喜剧 | 接受淑芬委托，打开笔记本，开始走访 |
| 第一章：天降大锅 | 从寻凶滑向爆笑乌龙 | 池塘误导、谷仓屋顶对峙、假蛋回收 |
| 第二章：温柔的反转 | 各说各话逐渐对上 | 黑猫线、老鼠情报、青蛙与薄荷鱼、红顶屋外勘察 |
| 漫画收束 | 释然 | 跳入红顶屋二层窗后，手帐展开为漫画，完成真相与团聚 |
| 二周目：释怀盘 | 吐槽与补完 | 全角色结尾对话、老鼠八卦与奶酪碎再收集 |

侦探笔记本负责记录与回看已取得的线索、证词和推测。主线占两页手帐，老鼠情报单独成页，用便签、大头针、红线和涂改痕保留推理过程。关键线索的独立 2D 调查玩法设计见 [19-关键线索调查解谜](../MissingEggDoc-main/docs/19-关键线索调查解谜.md)，运行时接入另行实施。

### 1.3 技术亮点

- **从 Lua 迁到 C# 与 JSON。** 初版用 Lua 编写逻辑并存储数据。当前运行逻辑为 C#，运行时数据为 JSON。对话定稿仍可由 Lua 表转换成 JSON，条件分支、选项锁、物证质询和分支解锁都挂在同一套变量上，改台词不必改交互代码。
- **完整的探案状态机。** 全局变量统一登记线索、章节进度和角色状态。调查点写入变量，对话节点读写变量，笔记本监听变量变化后自动入册、连线和划掉错误假设。
- **可玩的 PC 运行时架构。** `GameBootstrap` 在进入场景后拉起玩家、相机、对话、音频、经济和结局系统。当前玩法逻辑写在 `Assets/Scripts/Runtime/`，覆盖移动、交互、对话、笔记本、奶酪经济和漫画收束。
- **手帐式笔记本。** 主线条目、老鼠情报、连线和涂改都由游戏状态驱动。新线索在翻到对应页时渐显写入，错误推论保留划痕，推理过程本身成为界面。
- **三层表现。** 3D Lowpoly 场景负责空间和角色存在感，2D 立绘负责对话情绪，终局卧室揭晓由手帐漫画分镜完成，卧室内部不在 3D 场景里实时演出。
- **编辑器生产管线。** 项目内有对话图编辑器、NPC 与变量编辑器，以及 Lua 发布、变量校验、Lua 转 JSON 的菜单工具，保证策划文档、对话数据和运行时保持同一份事实。

## 二、AI 工具说明

本作品在开发中使用了 AI 工具，用于加快代码实现、角色构思和模型起稿。AI 产出的都是过程文件。进入工程的代码、人设、台词和模型，都经过人工审阅、修改和打磨后才定稿。

### 2.1 使用的工具与应用环节

| AI 工具 | 应用环节 | 过程稿 | 人工定稿 |
| --- | --- | --- | --- |
| Cursor | 程序开发 | 运行时脚本、交互逻辑、编辑器工具和数据转换代码的草稿与修改建议 | 对照策划文档核对变量、分支和场景接线，由开发者修改、联调并定稿 |
| GPT | 角色设计 | 角色性格、外形要点、关系位置和语气方向的文字草案 | 写入角色文档前由策划删改，统一时间线、说话边界和终局信息差 |
| Tripo | 三维模型起稿 | 角色或道具的生成网格、初版体块和姿态参考 | 检查比例、破面和风格后重拓扑、清理、绑到场景并手工调整 |
| 混元 | 三维模型起稿 | 另一路生成网格，用于比较体块、剪影和细节密度 | 与 Tripo 稿一样只作起稿，入场景前完成清理、减面和手工修型 |

### 2.2 AI 如何提升作品品质

**Cursor 负责写代码，把策划案更快落到可运行的系统上。** 本作的难点在于对话分支、物证锁、笔记本入册和场景状态必须使用同一套变量。Cursor 参与编写 C# 运行时、交互控制器、笔记本逻辑和 Lua 到 JSON 的数据管线，减少了重复样板代码的时间，让开发能把精力放在分支是否串线、线索是否漏记、存档是否完整这些品质问题上。生成结果会对照变量表和场景逐项核对，通过联调后才保留。

**GPT 负责生成角色设计，让群像在动笔之前就有清晰的性格差异。** 农场里有八个主要动物角色，加上缺席的农场主。GPT 用于整理每个角色的外形、语气和戏剧功能，例如淑芬的劳模母亲、大黄的老实失职、悲伤蛙的丧气误读、老鼠兄弟的情报商人。这些文字只作为人设草案。策划会按全案时间线删掉抢戏、泄底和人设漂移的内容，再定稿为角色文档和对话脚本。

**Tripo 和混元负责生成模型，用来快速试剪影和体块。** 两套工具分别产出角色和道具的过程模型，方便在 Lowpoly 农场里比较比例、轮廓和细节密度。生成网格不直接作为最终资产。入场景前会做清理、减面、修型，并按剧情需要的静态姿势重新调整，使模型符合「能演戏的动物」这一美术方向，而不是停留在生成器的默认可爱比例上。

### 2.3 人工把关

AI 在本项目里是起稿和加速工具。品质来自之后的人工工序：

- 代码以策划文档中的变量名、分支条件和场景挂点为准，生成代码经过阅读、修改和实机验证。
- 角色设计以全案时间线和信息边界为准，生成文案经过删改后才进入对话。
- 三维模型以农场的 Lowpoly 风格和角色剪影为准，生成网格经过清理和手工修型后才进入场景。

因此，玩家看到的角色、听到的台词、点到的交互和推进的案件，都是在 AI 过程稿之上由人工完成的版本。
